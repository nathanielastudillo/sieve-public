# Experiment 001 — Smoke loop on corpus_v003

- **Status**: completed (after debugging)
- **Date completed**: ~2026-04-15 (pre-summary session; finalize step 2026-04-17)
- **Node**: gpu-01 (single-node, 1× GB10 GPU)
- **Wallclock**: 275 min real training (3 × ~5500s gens) + ~20 min ensemble eval per gen
- **Result**: gen-2 best ensemble val_loss = **8.7315** (baseline `ln(16000) = 9.68`)

## Purpose

Validate the full SIEVE pipeline end-to-end on a small corpus before scaling:
- does the orchestrator correctly dispatch training?
- does ensemble evaluation (logit averaging) produce a meaningful val-loss signal?
- does generation-over-generation selection monotonically improve ensemble loss?

The goal was *plumbing* more than *performance*. Beat the uniform-over-vocab
baseline = success.

## Debugging history

Hit 3 orchestrator bugs before the run went clean:
1. `--corpus-dir` override didn't propagate to `evaluator.data_dir`
   → `FileNotFoundError: corpus/val.bin` at ensemble eval
2. Profile's `model.block_size=256` wasn't re-extracted to
   `evaluator._block_size_override` (stuck at 512 default)
   → `AssertionError: Sequence length 512 exceeds block_size 256`
3. `--results-dir` override didn't `mkdir` the directory and didn't
   rebuild `LineageDB` with the new path
   → `FileNotFoundError` at final spec write; `lineage.db` written to
     `results/lineage.db` (default) instead of override path

All three fixed in `controller/orchestrator.py` (uncommitted). See
`artifacts.md` for the lingering lineage.db debris from earlier attempts.

## Takeaways

- Pipeline works end-to-end
- Ensemble loss beats uniform baseline by ~0.95 nats on held-out val
- Individual members memorize train (loss < 0.05) but ensemble generalizes
  better — this is the SIEVE thesis in miniature
- Per-source density heuristic is saturated (every source returns 1.0);
  needs a sharper signal if we ever need to discriminate within a source
